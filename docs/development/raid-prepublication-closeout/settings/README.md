## 数字の根拠と限界
- 討伐は貢献0超のQA設定から、難度ごとの正の閾値へ切り替える。1,000 / 10,000 / 30,000 / 50,000は、参加記録だけで資格を得ず、救援の複数回参加条件より低い累積条件を設けるための丸い初期値。割合配分や順位報酬は追加しない。
- 初級1,000は既存正常戦闘のraw数千という実測より低く、既存例では1戦で到達し得る。ただし全編成に1戦達成を保証しない。中級以上の1戦当たりDamageは十分な実測がないため、戦数換算や最適値と称さない。
- 救援は明示済みの暫定候補を継承し、今回独自に戦闘数を増やさない。初級の既存例は必要戦数2を満たしてもDamage到達に5戦要した（raid_step6_reward_fixture_readonly.md、20,004）。「2戦で必ず報酬」はUIにも運営案内にも書かない。
- 報酬は既存100 EXP素材だけを使う。討伐は装備EXP300/500/800/1,200、救援はCharacter EXP200/300/500/800相当。異種EXPを共通通貨として合算しない。難度上昇の見返りを付けつつ、覚醒書・指南書・限界突破素材・ガチャ券・Diamond等の供給を追加しない。S素材を増やすだけなので、既存の名称・画像・Present受取・育成経路を使える。
- この数量は既存経済計算から一意に導かれた確定値ではない。新RoomはRoomごとに再取得可能で、旧レイドの日次制限より供給回数が増え得るため、小素材のみの初期運用案に絞る。旧報酬の稀少素材をRoom回数だけ反復付与する案は採用しない。
