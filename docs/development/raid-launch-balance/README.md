## 現候補の抽出と方針

変更前は7Areaのcanonical_raid_variantsを4難度で再利用し、難度別の敵実設定28行は無かった。各Area28M〜38Mの共有HP、共通ATK/DEF/SPD、元の5人を使い、Skillは共通Quest HARD poolから選択、敵装備は空だった。実効28組をvalidation-baseline.jsonとsimulation-before.jsonへ保存した。旧9月7日監査のDamageは読み込んでいない。現repo masterと現行Edge engineから新たに3seedずつ測定した。

既存目安はspecs/raid_room_rescue_v1.mdおよび当スレッドの人数・戦数。最低総合力は初級なし／中級160,000／上級200,000／超級240,000を維持。標準人数は3／4／7.5／15人、1人24h戦数2.5／3.5／4.5／5.5回。HP目安は標準24h Damage供給量の62.5%（15時間相当）。時刻分布は研究せず、均等供給換算と必要戦数で確認する。

現候補にはRaid Instance本人属性×2・Guild×2の実装がなく、Canonical個体属性1.2のみ。今回はReplay計算変更禁止を優先し、仮想倍率を注入していない。これらの倍率を別途接続する場合、今回HPは再評価が必要。

## 3. 敵編成・装備・Skillの変更

エリア名とパーティ名称を維持。全60Characterを難度別に配置し、37Skill・42Equipmentを使用する。通常CharacterのレベルStatから敵能力を決めず、Raid専用baseStatsへ装備の有効Statを加算する。敵装備は固定効果なしN/R、LB0〜2、難度別1/2/3/4枠。専用レベル・覚醒・Skill強化も記録し、上級以上の4Skillには覚醒1を記録した。

HP比例回復・Shield連打や全体STUNに偏った構成を避け、低難度を軽い支援と単体攻撃、高難度を範囲・Counter・DOT・能力変化を含む編成へ。初級は敵の先制即全滅を抑えた。上級ATK×0.65・超級ATK×0.50の圧力修正を1巡だけ行い、装備とSkillの多様性は維持した。

## 5. 未解消・公開時の注意点

- 上級のDamageが中級より低いAreaが残る。敵のSkill・編成と生存時間の差であり、同Powerの比較ではない。追加seed込みの比率は下記。1巡の制約に従い、追加探索や再度の敵修正はしていない。

| Area | 上級平均 / 中級平均 | 比率 |
| --- | --- | --- |
| 秋葉原 | 285,597 / 469,995 | 60.8% |
| 川崎 | 218,036 / 332,846 | 65.5% |

- 新宿超級はDamageばらつきが大きい。少人数側の10人×5回=50戦では低Damage側に寄ると不足する。標準15人側をHPの基準としている。全人数下限で12〜18時間を保証しない。
- 中級以上には30round上限到達が多い。設定された上限以内であり無限戦闘ではないが、Replay視聴の実秒数・操作体感は今回の数値検証対象外。
- 本人属性×2/Guild×2は現候補未接続。今回追加しておらず、既存の仕様差として残る。
- 3〜6seedは初期値決定の点検であり、確率保証ではない。均等供給換算は実際のログイン時刻・救援到着時刻の予測ではない。

## 貢献閾値への影響（値は変更しない）

実候補の討伐/救援ルールはnull/disabled。ここでは既存の未適用提案（討伐1K/10K/30K/50K超、救援2/16K・2/68K・3/205K・4/290K）を変更せず新HPとの割合だけ比較する。提案の採用・有効化ではない。旧累積PROGRESS報酬はRoom経路から分離されており、Roomで有効な追加の累計Damage報酬はない。
