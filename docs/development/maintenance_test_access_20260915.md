# メンテナンス中の本人限定テスト経路

## 実装候補

- DB許可表operations_maintenance_testersに登録したAuthユーザーIDだけ、メンテナンス中の既存操作停止ガードを通過できる。
- 許可は作成時刻から最大24時間。運用は必要最小限の時間とし、終了時に当該行を削除する。既定ユーザー・既定許可はない。
- 許可はゲーム操作全般のメンテナンス例外であり、ショップだけに限定するものではない。既存の所有者チェック・認証・RLSは維持する。
- SHOP/PAYMENT等の機能別CLOSEDは例外にしない。テスト対象機能をOPENにする工程は別途必要。
- UIは現在ログイン中の本人についてDB関数を確認し、許可中だけメンテナンス画面を通過する。15秒ごとに再確認。ユーザー切替や照会エラー時は許可を引き継がない。
- DBは各操作で有効期限を確認し、購入APIは検証済みAuth UIDとサーバー時刻で照合する。クライアント指定ユーザーIDや表示状態は権限の根拠にしない。
- 支払済み注文のWebhook/restoreは新規購入停止と分離する。

## 本番テスト開始まで

1. ガチャ担当の最新Git変更を取得し、GameContextのガチャ交換引数変更を保持して本差分を統合する。ガチャ担当が配信を担当するため、この作業からpush/Deployしない。
2. PreviewへDB候補を一度だけ適用し、専用QAで許可あり/なしの実画面と購入・Present受取を確認する。
3. 本番対象アカウントのAuth UIDをメール等から読み取り照合し、本人が使用するアカウントであることを確定する。Previewの同名ユーザーIDを転用しない。
4. 本番DB差分・アプリ反映と、対象UID・許可期限を示して承認後に適用する。MAINTENANCEは維持。
5. live Stripe設定・対象機能OPENを確認し、本人操作で実購入検証する。
6. 検証終了後、当該UIDの許可行を削除。メンテナンス解除は別判断。
