# 周回報酬・レイド発見案内の修正

## 表示と遷移

- 周回報酬の受取成功後、CASH・経験値・アイテムをアイコンと数量で直ちに表示する。
- 結果を閉じると街一覧へ戻る。街一覧を先に出して裏側の更新待ちで操作不能にしない。
- HUDの全体更新・ギルド貢献反映は受取結果の表示や操作ロック解除を待たせない。
- 戦闘側が結果表示を担当する場合、クエスト側の結果モーダルは重複表示しない。
- 発見レイドの正式バトル開始が成功したら、上部の「挑む」案内を非表示にする。
- 「あとで」を選んだ未開始レイドは案内を残す。発見時の部屋作成・参加者登録だけでは開始済みとしない。
- 開始実績はサーバーで判定し、再訪・再ログインでも維持する。

## 原因と修正

周回の `rewards_accrued` 初期値 `{}` が正常な探索報酬receiptより優先され、付与済みでも表示データが欠落していた。REPEATは保存済み探索receiptを正とする。過去に不完全なreceiptで完了した周回も、再受取時に再付与せず正しい内容を返す。

クライアントは探索を一覧から消した後に全体更新を待ち、結果ダイアログを遅延表示していた。受取成功時に結果を設定し、付随更新は非同期で行う。

レイド案内は既読状態だけで再表示を判定していた。正式な開始成功requestの有無を投影し、開始済みを表示対象から除外する。

## 検証

- `verify_quest_claim_responsiveness.mjs`: 全体更新とギルド処理が未完了でも結果・操作完了が返る。戦闘側モーダルの重複抑止を維持。
- `verify_quest_battle_result_liveness.mjs`: 既存の戦闘結果・遷移契約。
- `quest_progression_repeat_receipt_preview_rollback.sql`: 指定QAのみ、旧定義で再現FAIL、新定義でPASS。通常報酬と再受取の冪等性。
- `verify_quest_raid_encounter.mjs`: 未参加・参加済み・終了済みの表示判定。
- `verify_quest_raid_participation_preview.sql`: Preview実データの開始実績と投影の整合。

DB修正はPreviewのみ適用。本番変更なし。
