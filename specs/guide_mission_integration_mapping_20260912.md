## 1. 確定原則
初心者Mission = Guide + Achievement + Reward + Reflow。
Mission画面の操作学習を先頭に置かず、行動の達成・報酬をCustomer Journeyへ統合する。

MyPage → 次の推奨行動CTA → 対象ページ → 行動 → Mission達成 →「ミッション報酬を受け取る」→ 対象Mission → 報酬受取 → MyPage → 次の推奨行動。

- 報酬未受取は受取を優先案内するが、後続機能を既に経験しているユーザーのJourneyを巻き戻さない。受取を次機能解放の条件にしない。前回答の「受取成功でのみ次へ更新」は撤回。
- 自由行動、24h/48hでの学習、先行達成を認める。初日完走不要。Feature Coverageを主要な観測とする。
- Raid未開催は未経験/開催待ち。達成・報酬を付与せずGuild以降へ進める。開催後に再提示する。
- Gacha/Battle/Result中の強制遷移禁止。体験が終わってから報酬CTAを提示。
- 一つのサーバーAuthorityから行動実績・Mission達成・受取・推奨行動を投影する。クライアントに別の完了リストを作らない。接触、実行、受取は意味の異なる事実として区別する。
- Mission報酬はGame Cycleの学習、課金は学習済みCycleの無料でも越えられる時間的摩擦を短縮する役割。報酬新設・増量は自動的に行わない。

## 3. 各段階と3つのCycle
|段階|Customer Journey：学ぶこと|Game Cycle：接続|Motivation Cycle：次の欲求|
|---|---|---|---|
|MyPage|自分の状態と次の一手|開始/再訪→行動|まだ無料で得られるなら引きたい|
|無料Skill/Equipment|キャラ以外の獲得手段|獲得→装備|手に入れたものを使いたい|
|Character|編成・装備と戦力の関係|獲得→育成→実戦|強くなった戦力を試したい|
|Quest|派遣しCASHを稼げる|育成→資源→獲得/再育成|CASHでもう一度獲得・育成したい|
|PvP|他プレイヤーとの戦力比較|育成→対戦→再育成|勝ちたい・強みを確かめたい|
|Raid|同じ敵を他者と攻略する|戦闘→協力|一緒に戦える相手とつながりたい|
|Guild/Social|所属や交流で協力が続く|協力→Community|仲間のために育てたい・また来たい|
|Mission/Reflow|行動に報酬と次の目標がある|成果→報酬→再育成/再訪|次の報酬・成長を目指したい|

## 4. Authority・UIの提案
- 推奨行動と未受取報酬を同じ応答から返すが、別の状態として保持する。受取残数をGuide Stepとしない。
- 次の推奨行動は未経験機能を基本とする。既経験の後続機能は飛ばし、残った未経験を案内する。古い未受取への導線は残すが主CTAを過去Stepへ固定しない。
- 行動直後は該当Missionの受取CTAを優先。複数達成時は対象をまとめて表示できるようにし、同じ報酬をページごとに複製しない。
- 報酬受取成功→受取結果の確認→Home帰還。初心者導線から開いた場合だけ自動帰還し、通常のMission閲覧は既存の戻り先を維持。
- 別ページで既に受取済みなら再付与・再受取要求なし。失敗/応答消失時はサーバーを再取得し、残高と受取状態を合わせる。
- 日付が変わってもFeature経験を消さない。日次Missionの再出現と初回Journeyの進捗を同一視しない。
- 既存Missionの受取依存はreward状態に関する契約。これをそのまま初心者の機能経験条件へ転用しない。

## 5. 不足に対する提案（未FIX）
1. 無料Skill/Equipmentのカテゴリ別経験は既存成功Factを正規に統合して利用する。現在の日次1件を2件の独立報酬としては扱わない。追加報酬なしを第一案とし、無料2カテゴリを一つの獲得学習単位にまとめ、受取可能な既存報酬だけを案内する。カテゴリごとに必ず報酬を渡す要件なら、既存1報酬では不足するため別途報酬設計が必要。
2. Skill/Equipment装備MissionのP001→P002→P003受取依存を外す案。既存報酬量は維持。ただし解放が早まるユーザー数/既獲得装備からの遡及達成/追加で受け取れる量を算出してからFIXする。
3. TutorialですでにSkill/Equipment装備・Questを達成した場合はやり直し不要。Tutorial後の再利用を推奨することと未経験扱いを分ける。通常Missionが既に受取済みなら、既存日次など本当に未受取の報酬だけを提示。毎段階の追加報酬は作らない。
4. Guild閲覧は既存post_tutorial_guild_viewを接触として利用。加入/投稿報酬は実行した場合だけ。閲覧用の新報酬は提案しない。
5. Mission受取→Home帰還には初心者導線由来の遷移情報を追加する案。これは画面の戻り先情報であり、サーバーの達成・受取状態を置き換えない。

## 6. Monetizationとの境界
報酬は既存額を維持し、機能を一度体験して次へ進める役割。無料で進められる獲得/育成/資源/戦闘の反復を理解した後に、課金で時間や資源待ちを短縮する。
初心者Missionの完了に購入を要求しない。課金パック同等の追加配布、Special確率変更、商品内容変更は含めない。既存エナジードリンク・ガチャチケット報酬も同じ在庫/付与Authorityを利用し、別枠で重複発行しない。

## 7. 次の仕様FIXに必要な限定確認

- 日次リセット/前日未受取移送、先行達成、既受取のときも経験を保持できる投影。
- P002/P003の依存解消による受取時期・供給量への影響。
- 報酬なしの接触段階・既受取段階でも次へ進めるUI。すべての段階に報酬があるように表示しない。
